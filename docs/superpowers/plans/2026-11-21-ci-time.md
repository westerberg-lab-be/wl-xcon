# CI time: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (chosen) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **The PI's process rule of 2026-11-07 governs where it and the skill differ:** "a plan is a design and a list of tests, built once"; a fresh builder per task, **no per-task review**, **one whole-build review at the end**. A builder sees its own task, this plan's header, Global Constraints, Review Focus and Calls, the design, and the Interfaces blocks of earlier tasks.

**Goal:** Cut the mutation check's runner-hours without weakening any verdict: each nightly job maps every function to the tests that reach it, runs a mutant's likely tests first and confirms each catch on the unbroken code, runs the unbroken suite once a job instead of twice a module, caps the jobs it runs at once, and skips a night on which nothing changed.

**Architecture:** `tools/mutate.py` gains a coverage-built map (`--build-map`), a per-mutant selected run with a confirmation that falls through to today's full run (`--map`), and a lone restored run (`--restored`); its progress plugin switches coverage contexts and deselects to a list of ids. `tools/mutation_gate.py` builds one map for a job of at least `MAP_FROM` functions, passes it to every module, and runs one restored suite. `ci.yml` caps both mutation matrices and adds `nightly-plan` and `mutation-full-passed` around `mutation-full`.

**Tech Stack:** Python 3.13 (the mutation jobs' pin), pytest 9, coverage.py >= 7.10 (new, `dev` extra), GitHub Actions (`actions/cache/restore@v6`, `actions/cache/save@v6`), PyYAML (the `contract` extra) to read the workflow in tests.

**Spec:** `docs/superpowers/specs/2026-11-21-ci-time-design.md` (approved by the PI 2026-11-21, binding). Section numbers below (§N) are the spec's.

**Where:** a new worktree `.claude/worktrees/ci-time`, branch `ci-time`, cut from `main` after the console build merges (so `ci.yml`'s wl-xtasks `ref:` lines are already back to `main`). Its first commit adds this plan and the spec at the paths above. Ledger, git-ignored: `.superpowers/sdd/2026-11-21-ci-time/` (`progress.md`, a report per task, the suite logs, each sabotage's output).

## Global Constraints

From the design, verbatim where quoted:
- The rcfile `tools/suite_progress/coverage.ini`, `[run]`: `core = ctrace`, `source = wl_xcon`, `patch = subprocess`, `context = ${WLX_COV_CONTEXT-}` (§4.1); plus only what the installed coverage needs for a child's data to be combined (`parallel = true` if its subprocess page says so). It goes into `GLOBAL`.
- The map command is `python -m coverage run --rcfile=tools/suite_progress/coverage.ini -m pytest <SUITE_ARGV>`, through `_run_suite`, so `WLX_SUITE_PROGRESS` is set (§4.1).
- A test's context is its pytest node id, parametrization included. "Only labels that exactly equal a node id the progress file saw count as tests"; anything else "is counted and printed, but selects nothing."
- A target's lines: "every definition of the name, from its first body statement to `end_lineno`, read with `ast`".
- The map holds "test ids, per-function test lists, and a hash of every `wl_xcon/` and `tests/` file"; `--map` "refuses a map whose hash does not match the tree."
- Q2: "One unbroken run per job, which doubles as the coverage map, plus one restored run, instead of two per module."
- The selected run: "the same `limit` and `--maxfail=3`"; files positional; ids in a file named by `WLX_SUITE_SELECT`, "never put on argv". "It counts as a catch only if at least one failure or error is named"; exit 4 or 5 alone "is a harness fault, not a catch."
- Q1: confirmation runs "the same selected tests unmutated, up to and including the last one that failed"; a failure there sends the mutant to the full run and lists the test under `SELECTION NOT INDEPENDENT`.
- "A selected run never produces a `TIMED OUT` on its own." The full run is "exactly today's code path and today's verdicts."
- The verb column is unchanged (`caught` / `SURVIVED` / `TIMED OUT`). Tags: `[selected N of M]`, `[full, after N selected passed in Ss]`, `[full: no test in the map]`, `[full: selected failed unmutated too]` (and Call 5's two variants). A closing tally gives "each kind's count and seconds."
- `MAP_FROM = 15`, counted in functions in the job's plan. "Smaller shards run exactly as today." "A failed map build fails the job loudly."
- `coverage>=7.10` in `dev`; ADR-0004's line: "per-test line contexts, so a mutant runs the tests that reach it first". No pytest-cov.
- `max-parallel: 8` on `mutation-full`, `4` on `mutation`. `nightly-plan` on schedule and dispatch; `git ls-remote` for wl-preproc's and wl-xtasks' heads; every `mutation-full` shard checks out those SHAs; on `schedule` only, `actions/cache/restore@v6` with `lookup-only: true` and `continue-on-error: true`, key `mutation-full-passed-<sha>-<preproc>-<xtasks>`; `mutation-full-passed` with `needs: [nightly-plan, mutation-full]`, schedule only, every shard succeeded, saves the key. A workflow `concurrency` group for `schedule`, `cancel-in-progress: false`. The `test` job still runs every night. Dispatch never looks the key up.

- No timing claim: every saving and cost stays "an estimate" in code comments and docs, and each names the first nightly under this build as its measurement. The map's log line prints its own time.

## Review Focus

1. **A map built inside a measured suite.** The nightly's map run executes `tests/test_mutate.py`, whose own tests build toy maps: a coverage run inside a coverage run. The nested build must record only its own contexts, and the outer run must not be disturbed. Task 1's `test_a_map_built_inside_a_measured_suite_starts_clean`.
2. **A 65 KB parametrized id** (XC-331's bytes parameter) selected for a mutant: it reaches the plugin by file, is run, and no argv element carries it. Task 2's `test_a_65_kb_id_reaches_the_plugin_by_file_not_argv`.
3. **A selected id that is not collected** (an id that differs between runs, or a test renamed): counted and printed, never fatal, and the run is judged on what ran; with none collected, the mutant goes to the full run. Task 2's `test_a_selected_id_not_collected_is_counted_never_fatal`.
4. **A tree changed between modules**, now that Q2 removed each module's own baseline (a mutation the heal declined to restore, or an edit), **or a map file that is missing or corrupt**: refused before any mutant runs, never swept. Task 2's `test_a_tree_changed_since_the_map_is_refused_before_any_mutant`.
5. **A test that is red only under coverage** (it checks `sys.gettrace()`, or a bounded wait it now misses): the map build refuses, naming the test, and writes no map. Task 1's `test_a_suite_red_under_coverage_refuses_the_map`.

## Calls taken in this plan

1. **Three CLI modes on `mutate.py`.** `--build-map PATH` (heal, the map's run, the map written); `--map PATH` (with `--all` or a function: the baseline is read from the map, and no baseline or restored suite runs in this call); `--restored` (heal, one unmutated suite). The gate is `--map`'s only intended caller and runs `--restored` once, after its last module.
2. **A mutant's limit under `--map` is `_mutant_limit(map.seconds)`**, the map run's own wall time under coverage. That is no shorter than today's limit, so it can only turn a would-be `TIMED OUT` into a named catch or a survivor, never into a catch with nothing named. It costs time only on a hang. The first nightly measures both times.
3. **Q2's guard is the map's hash, checked after the heal at the start of every `--map` call.** Today each module's baseline would go red on a tree left broken by the module before it. Under Q2, the hash refuses the tree instead (Review Focus 4).
4. **Selected files are passed in the order of their first test in the map's run order**, so a selected run keeps the baseline's relative order. The ids go in a JSON list in the `WLX_SUITE_SELECT` file.
5. **Two more phrasings of the fall-through tag**, so a tag never says "passed" for a run that did not pass: `[full, after N selected timed out in Ss]` and `[full, after N selected ended with no test named (exit C) in Ss]`. They are the same kind in the tally as `passed`.
6. **The confirmation runs with no `--maxfail` and the same limit.** A confirmation that times out counts as not confirmed (`[full: selected failed unmutated too]`, listed with "(timed out)").
7. **Selected ids that are not collected** are counted in the tally, never fatal (Review Focus 3).
8. **The map covers every function of every `wl_xcon/*.py`**, not just the job's shard. Its JSON stores each function's tests as indices into `tests`.
9. **`_run_suite` strips every inherited `COVERAGE_*` variable, `WLX_COV_CONTEXT` and `WLX_SUITE_SELECT` from each child's environment**, then sets its own. A nested suite run then starts unmeasured (Review Focus 1).
10. **Toy trees mirror the repository's layout** (`wl_xcon/`, `tests/` under `tmp_path`), so the shipped rcfile and `tree_hash` run unchanged in tests.
11. **The pitfall is a new row with the next free P number** (P30 at the console build's head), severity High, as with the other harness-shaped risks.
12. **Backlog.** XC-500 is narrowed and takes the shard count to revisit. One new line covers `MAP_FROM` tuning. A test that `SELECTION NOT INDEPENDENT` names gets its line when a nightly names one, by whoever reads that nightly. None exists yet.
